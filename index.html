発想の型

ここにあるゲームは、すべて同じ六つの型でできています。新しく作るときも、この六つを満たしているかを確かめてください。

  1. 01

    題材はファンタジーではなく、全員が知っている現実

    台風、カレンダー、満員電車、年賀状。ルールの説明がほぼ要らず、だれにでも一瞬で伝わります。説明が三行を超える題材は、まだ「あるある」になっていません。

    例朝の満員電車／月末の決裁書類／年末の郵便局

  2. 02

    抽象的な概念を、物理にする

    予定は重力で崩れる箱、台風は予報円つきの円、日本列島は掴める物体。現実のしくみのルールを、そのままゲームの物理法則に翻訳します。比喩ではなく、当たり判定と重さを持たせるのがコツです。

    例「混雑」→ 奥へ押し合う乗客の体／「決裁」→ ベルトを流れてくる書類

  3. 03

    現実ではありえない権限を、一つだけ与える

    「日本列島を動かせる」「他人の予定を無理やりねじ込める」。現実では絶対に持てない力を一つだけ渡します。この倒錯が、笑いと快感の核になります。二つ以上渡すと、ただの万能ゲームになります。

    例乗客を指でつまんで押し込める／太平洋高気圧を指で動かせる

  4. 04

    失敗を、いちばんの見せ場にする

    予定が崩れる箱の雪崩、上陸した地方名のテロップ、「ドアが閉まりません」の車内放送。負けた瞬間がいちばん面白いように作ると、もう一回遊びたくなり、だれかに見せたくなります。失敗の理由は必ずプレイヤーの操作に帰るようにして、理不尽な負けは作りません。

    例タクシー代の領収書が印刷される／監査の付箋が書類を埋める

  5. 05

    本物のデータと UI にこだわる

    気象庁の台風名リスト、実在の海岸線、本物の稟議書の決裁欄、駅の発車標。実在感が没入を生み、「これ見て」と言いたくなる理由になります。データは一次情報を確かめ、出典をゲームの中に書きます。乱数ではなく実データか固定の並びを使うので、覚えれば必ずうまくなります。

    例桜の満開日の平年値／実在の郵便番号／路線のラインカラー

  6. 06

    操作は、一つに絞る

    ドラッグだけ、タップだけ、スライドだけ。スマホを縦に持って、親指一本で遊べるようにします。操作を増やしたくなったら、それは題材の物理化がまだ足りないサインです。

    例ドラッグして離す／タイミングでタップ／縦にスライド

参加する

GitHub がはじめての人の練習場所でもあります。issue を書く、名前を一行足す、ゲームを一本つくる。どれも同じだけ立派な参加です。

  1. やさしいissue で話してみる「これをゲームにしてほしい」「ここが分かりにくい」Issues
  2. ふつう名前を一行足してみるブラウザだけで、はじめてのプルリクエスト手順
  3. じっくりゲームを一本つくる雛形をコピーして、HTML 一枚で。ビルドは要りません雛形
