# 梅雨前線ディフェンス（仕様書）

> ステータス: **実装済み**（`index.html`・No.05）

## 発想の型

| 要素 | 内容 |
|---|---|
| 題材（みんなが知っている現実） | 梅雨入りを1日でも遅らせたい洗濯民の願い |
| 物理化（概念→物理オブジェクト） | 太平洋高気圧＝前線が入り込めない円盤。北上してくる梅雨前線は円盤の南の縁でせき止められ、縁に沿って曲がる。せき止められた（停滞した）前線の下にある地方には雨が積もる |
| 権限（現実ではありえない） | 太平洋高気圧を指で好きな場所へ動かせる |
| 技術（習熟でクリア可能にするもの） | 守る地方の代表地点のすぐ南に高気圧の南の縁を置きつつ、せき止めた前線ができるだけ海の上に乗るよう東西の位置を選ぶ。日が進むほど前線は北へ押し、必要な押し込みが深くなる |
| トレードオフ | 浅いと守る地方が梅雨入り／せき止めた前線が別の地方の上に乗り続けると大雨（300mm）／自然な位置より約5.5°（120px）以上南へ押し込むと、前線が高気圧の北側へ乗り越えて一気に梅雨入り |
| 失敗の見せ場 | 気象庁の発表文どおりのテロップ「関東甲信地方は梅雨入りしたと見られます。」（地方名は気象庁の表記どおり。九州南部・東北南部・東北北部は「地方」を付けない）が画面を覆い、ベランダの洗濯物がぬれる → 判子「梅雨入」／大雨は「前線が停滞し、◯◯地方で大雨となっています。」→ 判子「大雨」 |
| クリア | 丸印「晴天」 |
| 操作（スマホ親指・1操作） | 画面のどこでもドラッグすると、高気圧が指と同じだけ動く（相対ドラッグ。親指は画面下半分のまま）。PC は矢印キーでも可 |

## 見た目（ゲーム固有）

- HUD: 天気図の凡例の枠（下端を二重罫）。左=守る地方と面番号、右=あと何日・いちばん雨が積もっている地方の雨量（210mm を超えると朱）
- 結果シート: 地方気象台「梅雨入りに関するお知らせ」の書式（（見出し）（本文）（参考事項）の表）。墨は天気図の紺 #1B2A44、朱は判子と警告だけ
- 判子: 梅雨入り＝角印「梅雨入」／大雨＝角印「大雨」／クリア＝丸印「晴天」

## データ

- 梅雨入り・梅雨明けの平年日（1991〜2020年の平均）: 気象庁「過去の梅雨入りと梅雨明け」 https://www.data.jma.go.jp/cpd/baiu/ （地方別ページ kako_baiu01〜12.html）
- 発表文の書式: 気象庁各地方気象台「梅雨入りに関するお知らせ」（例: 甲府地方気象台 令和7年6月10日 https://www.data.jma.go.jp/kofu/image/2025/20250610_tsuyu.pdf ）
- 地方名の表記: 気象庁「2025年（令和7年）の梅雨入りと梅雨明け（確定値）」 https://www.data.jma.go.jp/cpd/longfcst/seasonal/202508/tsuyu2025.pdf
- 海岸線: Natural Earth 1:50m（パブリックドメイン）を簡略化
- **概略値**: 前線の自然な北上（平年日に代表地点へ届くように日付→緯度を折れ線で結んだもの、6月15日以降は 0.28°/日で外挿）、前線の傾き・うねり、地方の代表地点、雨量のモデル（停滞した前線1点あたり 45mm/日・2日で減衰・300mmで大雨）は実測値ではない

## 検証

- 乱数で勝敗を決めない（前線の動きは日付だけで決まる。乱数は雨粒の描画のみ）
- 制作時に `index.html` の `// ==CORE==` 〜 `// ==/CORE==`（DOM 非依存の物理）を node で切り出してシミュレーションし、全6面にクリアできる置き方があることを確認（固定位置の全探索・±8px の手ぶれを入れた検証の両方）
- 天気図の文字（見出し・緯度経度・等圧線の値・高/低・守る地点・梅雨入り・雨量・小窓の見出し・ガイド）は毎フレーム優先度順に配置し、重なる・画面外にはみ出す位置には置かない（必須ラベルは候補位置を順に試す）。scratchpad の `baiu/overlap.js` で全6面 × 4通りの操作 × 3画面サイズ（390×844 / 1280×720(H=700) / 360×740）を走査し、重なり0・はみ出し0・必須ラベルの欠落0・HUD の見切れ0を確認
- 攻略の型: 高気圧を守る地方の真上ではなく東か西へずらし、南の縁を代表地点のすぐ南（20〜40px）に置く。真上に置いて縁を代表地点の 15px 南にする素朴な置き方は、関東甲信で東海が大雨になって失敗する

## 実装の約束（GAME HACK 共通）

- 乱数で勝敗を決めない。出現パターンは実データか固定シーケンス（＝覚えられる・RTAが成立）
- 失敗は必ずプレイヤーの操作・判断に帰因できる（理不尽な死なし）
- スマホ縦持ち・親指操作を基本に（タップ領域 44px 以上・safe-area 対応）
- 単一ファイル `index.html`（このディレクトリに置く）。外部依存なし・ビルド不要
- 共有ボタン（𝕏）とポータルへの導線を入れる
- データの出典をゲーム内に明記する
