# ダム放流オペレーション（仕様書）

> ステータス: **実装済み**（`index.html`）。改善の提案は issue へ。

## 発想の型

| 要素 | 内容 |
|---|---|
| 題材（みんなが知っている現実） | 大雨の日のダム管理所の「放流判断」。治水は両方向に失敗がある |
| 物理化（概念→物理オブジェクト） | 雨＝流入量のカーブ、放流＝ゲート開度、貯水＝ダム断面図の水位（洪水時最高水位・常時満水位・最低水位）、治水＝下流の水位観測所の量水標と堤防 |
| 権限（現実ではありえない） | この先の雨がすべて分かる（予報が100%当たる）。操作盤の表に、この先の流入量カーブ（破線）と「堤防まで」の放流上限が最後まで出ている |
| 技術（習熟でクリア可能にするもの） | 雨の山が来る前に先に流して空きを作る（事前放流）。ただし流しすぎると最低水位割れ・雨のあとの貯水率不足で渇水 |
| 失敗の見せ場 | 氾濫: 放流警報のサイレン → 堤防を越えた水が町に入り、家・車・人が水に浸かる →「氾濫」判子。渇水: 湖底が干上がり取水制限のテロップ →「渇水」判子 |
| 操作（スマホ親指・1操作） | 右下のレバーを縦にスライドしてゲート開度（0〜100%）を決める。PC は ↑↓ キーで 5% ずつ |

## データと概略値

- **実データ**: 時間降水量（気象庁 過去の気象データ https://www.data.jma.go.jp/stats/etrn/ の hourly_a1）。値は `index.html` の `STAGES[].rain` にそのまま入っている
- **概略値（モデル）**: ダムはモデルダムで実在のダムではない。諸元（最低水位 EL172.0m・常時満水位 EL190.0m・洪水時最高水位 EL198.0m、利水容量 1,500万m³・洪水調節容量 1,200万m³）、流入量（集水面積×流出係数0.7の線形貯留モデル。集水面積は面ごとに 395/279/195/134 km²）、下流の支川流量と水位（堤防天端 7.5m＝合計 700m³/s）はすべて計算上の値

## ルール

- 0.05時間刻みでシミュレーション（1秒で0.7時間進む。1面およそ1分）
- 失敗: 下流の流量（放流量＋支川）が堤防の高さを超える＝氾濫／貯水位が最低水位を割る＝渇水／雨のあとの貯水率が80%未満＝渇水（取水制限）
- 洪水時最高水位に達すると流入量と同じだけ放流する（異常洪水時防災操作）。そのとき流入量が堤防を超えれば氾濫

## クリア可能性の根拠

`index.html` の `STAGES` と `SIM` ブロックをそのまま読み込む検証スクリプトで確認した。

- 動的計画法（開度51段階×0.05時間）: 全4面クリア可能。堤防流量の余裕は 1.60 / 1.40 / 1.46 / 1.35 倍
- 人間向けの粗い方策（1時間ごとにだけ、5%刻みで開度を変える。「ある時刻から下流が堤防流量の80〜85%になる開度で流し続け、貯水が一定量を割ったら閉める」）でも全4面クリアできる組み合わせが 178 / 26 / 19 / 22 通りある
- 全閉・全開・流入量＝放流量の3つの単純操作は、どの面でも氾濫する

## 実装の約束（GAME HACK 共通）

- 乱数で勝敗を決めない（雨は実測値の固定列）
- 失敗は必ずプレイヤーの操作・判断に帰因できる
- スマホ縦持ち・親指操作（タップ領域 44px 以上・safe-area 対応）
- 単一ファイル `index.html`・外部依存なし・ビルド不要
- 共有ボタン（𝕏）とポータルへの導線・データの出典をゲーム内に明記
